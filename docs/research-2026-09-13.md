# GitHub 调研与源码核查

调研日期：2026-09-13，Asia/Kuala_Lumpur。

## 1. 研究方法与结论可信度

本次同时核查了项目官方 README、Chrome 官方文档以及六个仓库的真实检出源码；提交 SHA 固定在 `../references.lock.json`。没有安装这些项目的依赖，也没有把 README 宣称当作本产品已通过的浏览器测试。

评估维度为：本地地址直读、文章目录、文件夹树、图表覆盖、样式、浏览器架构、安全默认、许可证和持续维护成本。Star 仅记录快照，不用作可靠性排名。

**推荐结论：以 docu.md 的阅读与富渲染模块为主要复用候选，建立独立、裁剪后的 Chrome 产品。** 它在本次六个候选中最贴近功能广度要求；是否可作为正式代码基线，仍须通过技术方案中的 S0 构建、权限和安全验收。这里不是“全 GitHub 最强”或“已经测试无问题”的断言。

## 4. docu.md 源码核查

以下路径均相对于 `../参考工程/docu-md/`，证据对应锁定的 109fcfc7cb197bbab5b0517485ab7cd3934f13e5。

### 4.1 值得直接借鉴的分层

- `src/core/markdown-processor.ts`：Markdown 解析与 HTML 处理。
- `src/core/viewer/`：viewer kernel、controller、host、session 等阅读会话分层。
- `src/renderers/`：Mermaid、PlantUML、DOT、Vega、ECharts、draw.io、Canvas、Infographic 等独立 renderer。
- `src/renderers/host/` 与 `src/renderers/worker/`：渲染宿主和协议。
- `src/ui/toc-panel.ts`、`src/ui/diagram-lightbox.ts`：目录与图表交互。
- `chrome/src/workspace/workspace.ts`：目录选择、文件树、最近工作区及拖放文件处理。
- `chrome/src/host/background.ts`：Chrome 消息和本地读取宿主。

这些能力可以减少重复开发，但需要做依赖闭包、构建入口和安全边界审计。它们目前仍只存在于参考检出中，没有导入主项目产品代码。

### 4.2 文件树不是从零开始

`workspace.ts` 已调用 `showDirectoryPicker({ mode: 'read' })`。最近工作区保存了文件夹 handle，并在用户点击时调用 `requestPermission`。因此本项目可以复用工作区设计，而不是额外搭建本地服务器或 Native Messaging 服务。

该能力仍依赖用户主动选择和授权。某些参考项目通过解析浏览器目录页面实现文件树，这不是本项目采用的正式权限方案，也不能视为绕过 Chrome 或 macOS 权限的可靠方法。

### 4.3 权限与网络配置必须裁剪

`chrome/manifest.json` 当前申请 file、HTTP、HTTPS 主机权限，另有 storage、unlimitedStorage、offscreen、scripting、contextMenus、alarms。扩展页 CSP 配置包含网络字体来源；HTML 预览 sandbox 的 CSP 允许部分 CDN 与更宽的执行能力。

这说明配置允许这些能力，**不等于已经证明它实际联网、上传文档或违反应用商店政策**。本项目定位为安全、本地优先的只读阅读器，因此不继承执行型 HTML 预览、CDN 执行或默认全站访问。

### 4.4 Mermaid 与 HTML 安全默认

`src/renderers/mermaid-renderer.ts` 当前有 `securityLevel: 'loose'` 和 `htmlLabels: true`。本项目默认使用 strict，并为 HTML labels、SVG 与链接建立明确的安全兼容集；不允许文档 frontmatter 或 Mermaid 指令覆盖安全策略。

`markdown-processor.ts` 有允许原始 HTML 的处理选项，也存在 `sanitizeRenderedHtml` 等自有清洗逻辑。因此不能简单宣称“上游完全没有清洗”；真正需要验证的是允许元素、属性、协议、SVG 引用以及最后一次 DOM 注入的边界。

### 4.5 PlantUML 不能宣传为全量原生兼容

`plantuml-renderer.ts` 使用 `@markdown-viewer/draw-uml` 把 DSL 转成 DrawIO XML，再进行图形渲染。这不是原生 Java PlantUML 的完整运行环境。复杂宏、预处理、include、主题、插件等不能在缺少测试时宣称完整支持。

本项目用固定测试语料公布支持的图型和语法；无法解析时显示清晰诊断及原文。默认不会把内容发送给公共 PlantUML/Kroki 服务来掩盖兼容缺口。

### 4.6 Vega 的 CSP 方向值得保留

`vega-renderer.ts` 已使用 `vega-interpreter` 的 `expressionInterpreter`，可以参考它处理禁用动态 JavaScript 代码生成的环境。还必须单独限制外部 data URL、image、loader 等网络输入；禁止 eval 不等于没有网络泄漏。

### 4.7 构建与依赖需要独立整理

源码 package 版本为 5.3.0。它声明 Mermaid `^11.12.2`、KaTeX `^0.16.27`、unified `^11.0.5` 等范围；这些不是已经锁定的安装版本。本次根目录未发现包管理器 lockfile，不能声称当前参考提交能够在任意日期解析出相同依赖。

Chrome 构建使用 esbuild，但构建脚本还调用 Slidev shell 构建；根依赖同时含 AI SDK、Vue/Slidev、VS Code 与其他平台相关内容。这不证明它们全部进入 Chrome 产物，需要用构建图确认。正式产品只保留被选模块的依赖闭包，生成并提交自己的锁文件，不直接继承整套安装体积和构建流程。

上游 test 命令依赖 fibjs，不能把本机执行普通 `npm test` 当成无环境要求的验证步骤。产品测试需要重新定义为明确的、可在 CI 复现的命令。

## 5. 许可证与公开交付

选择 docu.md 衍生路线意味着产品应按 GPL-3.0-only 兼容方式交付，保留所用上游源代码的版权、许可证与修改记录，并按实际分发方式履行相应源码义务。不能仅改仓库名称后改标 MIT。公有 GitHub 仓库与该方向相容，但“仓库公开”本身不替代许可证和第三方声明检查。

NCSA 与 MIT 参考内容同样需要保留相应声明；ReadMD 在本轮只作为交互设计参考。当前没有把任何候选的产品源码复制到主仓库。

这是一份工程选型与合规准备说明，不是对最终依赖组合的法律意见；发布前必须根据实际选入文件和锁定版本再次核对。
